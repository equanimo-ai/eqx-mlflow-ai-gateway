# eqx_mlflow

Equanimo extensions for the MLflow AI Gateway. Each Equanimo tenant (`t_acme`) gets its own
MLflow workspace (`t-acme`), and the server refuses to run in a configuration that would let
tenants see each other's data.

## Running

```bash
# Local dependencies: Postgres, Redis, and LocalStack (Kinesis + SQS stand-ins).
docker compose -f docker-compose/eqx-local/docker-compose.yml up -d

export MLFLOW_CRYPTO_KEK_PASSPHRASE=<unique high-entropy secret>
export MLFLOW_ENABLE_WORKSPACES=true
export MLFLOW_WORKSPACE_STORE_URI=eqx+postgresql://mlflow:mlflow-dev-only@127.0.0.1:5432/mlflow
export EQX_TENANCY_ENABLED=true

python -m eqx_mlflow server --backend-store-uri postgresql://... --app-name basic-auth
python -m eqx_mlflow tenants create t_acme
```

`python -m eqx_mlflow server` checks the configuration, then runs `mlflow server` with the same
arguments. It needs the `auth` extra (`pip install "mlflow[auth]"`) when tenancy is on.

## Configuration

| Variable | Values | Default |
| --- | --- | --- |
| `EQX_TENANCY_ENABLED` | `true`, `false` | `false` |
| `EQX_USAGE_LEDGER_ENABLED` | `true`, `false` | `false` |
| `EQX_EVENT_PUBLISHER` | `none`, `log`, `kinesis` (requires the usage ledger) | `none` |
| `EQX_BUDGET_SOURCE` | `none`, `file`, `cost_explorer` | `none` |
| `EQX_POLICY_ACTIONS` | `none`, `sqs` | `none` |
| `EQX_AUTH_MODE` | `basic`, `equanimo` | `basic` |
| `EQX_EXPECTED_REPLICAS` | positive integer | `1` |

The ledger, event, budget and policy settings are parsed and validated here but are not acted on
yet.

The server refuses to start when:

- `MLFLOW_CRYPTO_KEK_PASSPHRASE` is unset or is MLflow's development default.
- `EQX_EXPECTED_REPLICAS` is above 1 and `MLFLOW_GATEWAY_BUDGET_REDIS_URL` is unset. The
  in-memory budget tracker counts spend per process.
- `EQX_TENANCY_ENABLED` is true and workspaces are off, or `MLFLOW_WORKSPACE_STORE_URI` is not an
  `eqx+<database>://` URI, or `--app-name basic-auth` is missing.

## Tenants and workspaces

- `workspace = tenant_id.replace("_", "-")`. Tenant IDs match `t_[a-z0-9_]+`.
- Workspaces are created by an admin with `python -m eqx_mlflow tenants create <tenant_id>`.
  A request for an unprovisioned tenant gets 404; nothing is created on demand. Grant users
  access with MLflow's own workspace roles.
- The `default` workspace is closed. Requests must name a tenant workspace in
  `X-MLFLOW-WORKSPACE`; one without it, or naming `default`, is rejected.
- `/health` and `/version` do not need a workspace header, so load balancer probes work.

`MLFLOW_WORKSPACE_STORE_URI` must be set explicitly. Without it MLflow falls back to the plain
tracking URI and uses its own workspace store. The URI scheme selects the provider, so a driver
suffix such as `eqx+postgresql+psycopg2://` is not supported.

### Moving existing data into a tenant

`mlflow db move-workspace` reads workspaces through the configured workspace store, which hides
`default`. To move data out of `default`, run it with `MLFLOW_WORKSPACE_STORE_URI` unset.

## Packaging

`pyproject.toml` and `pyproject.release.toml` are generated by `dev/pyproject.py`. The plugin is
part of the `mlflow` and release distributions only, not skinny or tracing.
